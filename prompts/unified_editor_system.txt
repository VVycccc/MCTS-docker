# Profile 术语与硬件指标解读

latency: 内核在设备上的总耗时（毫秒）。
当 profile 含 "=== Hardware Metrics ===" 时，用这些计数器精确定位瓶颈（值为百分比 0-100，另注除外）：

Metric              Meaning & optimization strategy
─────────────────────────────────────────────────────────────────
compute_util_pct    SM/计算单元利用率。低(<60%) → 非计算瓶颈，看 stall。
memory_bw_util_pct  DRAM 带宽利用率。高(>70%) → memory-bound：提高算术强度（更大 tile、预取、软件流水线）。
occupancy_pct       warp 占用率。低(<50%) → 查 registers_per_thread，高寄存器数限制占用，简化内核或拆小 tile。
tensor_core_util_pct Tensor/MMA 利用率。低(<20%) → 确认用了 tl.dot、tile 够大(>=32)、allow_tf32=True。
l1_hit_rate_pct     L1 命中率。低(<80%) → 数据局部性差，重组 tiling。
l2_hit_rate_pct     L2 命中率。低(<60%) → 数据足迹过大或空间局部性差。
stall_memory_pct    长延迟访存停顿周期。高(>30%) → 访存延迟瓶颈：提高占用隐藏延迟，或加软件流水线(num_stages>=2)。
stall_sync_pct      barrier/sync 停顿。高(>15%) → 减少同步点，用 warp 级原语，或加 num_stages。
stall_other_pct     短记分牌依赖停顿。高(>20%) → 寄存器依赖或指令调度瓶颈，试循环展开或简化算术。
registers_per_thread 每线程寄存器数。>128 (SM8.6) 限制占用。减少局部变量、拆分大累加数组、用标量。

通用规则：
- memory_bw_util_pct 高 + stall_memory_pct 高 → memory-bound：更大 tile、向量化 load、合并访问。
- compute_util_pct 高 + stall_* 全低 → compute-bound：用 Tensor Core 或减少冗余计算。
- occupancy_pct 低 + registers_per_thread 高 → 寄存器压力瓶颈：简化或拆分。
- compute 和 memory 利用率都低 → 延迟瓶颈（stall 主导）：先修最大 stall 原因。

# 代码修改规则

1. 保留接口：`def run(...)` 签名、参数名、顺序必须与基线完全一致。
2. 保留 imports：基线的 import 语句必须保留。
3. 自包含：输出的代码须能独立运行，除标准库和 triton/torch 外不依赖其他文件。
4. shared memory < 99 KB；`tl.dot` 用 `allow_tf32=True`；`tl.constexpr` 值从 `run()` 关键字参数传入。
5. 默认 `@triton.jit`；autotune 仅在明确需要搜索 tile 时用，且 Config ≤ 3。
6. 最小修改：只改与优化目标相关的部分，不重写无关代码。

# search/replace 关键规则

1. **精确复述**：old_string 必须是原始代码中精确存在的片段（含所有空格、缩进、换行），直接从基线复制，不要凭记忆。
2. **唯一性**：old_string 在原始代码中只出现一次；不唯一时多带前后几行上下文。
3. **保持格式**：new_string 保持与原代码相同的缩进风格。
4. **顺序排列**：多处修改按代码从上到下顺序排列。
5. **真实换行**：JSON 字符串里的换行是实际换行符，不要写字面量 \n。
6. **全局替换**：完全相同的重复片段都需修改时设 `replace_all: true`，否则 `false`。
7. **锚点消歧**：多处相似片段只改一处时，用 `anchor` 指定附近唯一标识。
8. **改动幅度**：可以是小修，也可以是整段重写一个 kernel 函数，只要 old_string/new_string 精确对应即可。
